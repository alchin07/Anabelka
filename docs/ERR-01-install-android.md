# ERR-01 — установка и проверка Android / KSWEB

Код находится только в `feature/error-display-modes`. Основа: `feature/category-manager`, `69fe3bcacd64b2d74e7728d6c869d61ee48f0d37`. Основной магазин автоматически не обновлялся. Сначала требуется проверить отдельную копию; эта инструкция не является командой на установку в рабочий магазин.

## 1. Подготовить отдельную копию

Сделайте ручную контрольную копию перед установкой. Не изменяйте текущий проект `/storage/emulated/0/htdocs/Anabelka`, его конфигурацию, БД `anabelka`, каталоги фотографий, заказов, `Anabelka-chat-test` и `visitor-counter-test`.

В Termux можно скачать новую ветку отдельно:

```sh
ERR01_ROOT="/storage/emulated/0/Anabelka-ERR01-test"
mkdir -p "$ERR01_ROOT/htdocs" "$ERR01_ROOT/sessions"
git clone --single-branch --branch feature/error-display-modes \
  https://github.com/alchin07/Anabelka.git "$ERR01_ROOT/htdocs/Anabelka"
```

Если папка назначения уже существует, остановитесь и проверьте её содержимое. Не применяйте `git reset --hard`, `git clean`, переключение исходного магазина или операции со stash.

В KSWEB настройте отдельный Apache host/порт, например **8788**, с DocumentRoot:

`/storage/emulated/0/Anabelka-ERR01-test/htdocs`

Тогда адрес копии — `http://127.0.0.1:8788/Anabelka/`. Важно сохранить имя вложенной папки **Anabelka**: существующий проект использует этот префикс в ссылках и ресурсах. Размещение копии на обычном рабочем порту под другим именем может направить ссылки в основной магазин.

Используйте отдельный тестовый процесс/host. Не меняйте глобальный `display_errors` и настройки PHP основного магазина. Если отдельный host нельзя настроить без воздействия на рабочую среду, сначала выполните CLI/HTTP-проверки на отдельном стенде и отложите нативную проверку KSWEB.

## 2. Подключить только тестовую БД

До первого открытия сайта создайте **отдельную** базу `anabelka_err01_test` и отдельного пользователя с доступом только к ней. Используйте экспорт схемы из уже сделанной резервной копии и искусственные тестовые данные. Не выполняйте тесты ошибок в `anabelka` и не подключайте тестовую копию к ней даже временно.

В **новой копии** исправьте `config/database.php`: имя БД — `anabelka_err01_test`; адрес, порт и учётные данные — от тестовой MariaDB. В репозитории исходный пример конфигурации указывает `anabelka`, поэтому этот шаг обязателен. Не публикуйте локальные реквизиты в Git.

Схема ERR-01 не требует миграции или новых таблиц. Используется существующая `app_settings`; ключ `error_display_mode` создаётся обычным сохранением в настройках. Пока ключ отсутствует — действует `production`.

## 3. Отделить PHP-сессии

Только в тестовом `index.php`, **после** `ErrorHandler::register(__DIR__)` и до запуска `App`, добавьте:

```php
session_name('ANABELKA_ERR01_TEST');
ini_set('session.save_path', dirname(__DIR__, 2) . '/sessions');
ini_set('session.use_strict_mode', '1');
```

Каталог sessions должен существовать, быть доступен PHP и находиться вне DocumentRoot. Это локальная настройка стенда; не переносите её в основной магазин или коммит модуля. Не используйте действующие сессии администратора и реальные пароли для тестовых аккаунтов.

## 4. Проверить доступ и сохранение

Откройте `http://127.0.0.1:8788/Anabelka/admin/system/error-display` под тестовым Разработчиком (`owner`). Раздел «Режими відображення помилок» также зарегистрирован в группе «Система» конструктора админ-панели; при необходимости добавьте службу через существующий конструктор.

1. Начальный режим — «Робочий сайт».
2. Выберите «Розробка», нажмите «Зберегти режим» и сначала отмените подтверждение: значение должно остаться прежним.
3. Повторите и подтвердите. Должно появиться фирменное уведомление; после обновления страницы выбор сохраняется.
4. Проверьте журнал действий: `system.error_display_mode.update`, ID администратора, `old_mode`, `new_mode`.
5. Перезапуск **изолированного** PHP/Apache-процесса не должен сбрасывать настройку. Не перезапускайте рабочий сервис ради этого теста.
6. У `store_owner` и другого администратора прямой доступ даёт 403, служба недоступна, POST не меняет настройку.
7. POST без корректного CSRF отклоняется с 403.

## 5. Проверить отображение

Примеры обоих режимов внутри настроек и GET-раздел `/admin/system/error-test` сами не создают ошибок. В последнем сохраняется старый отдельный POST-тест настоящего исключения: используйте его **только на изолированном стенде**.

Проверьте на тестовой копии:

- Несуществующий публичный маршрут: 404; Разработчику в development доступна очищенная карточка, посетителю — обычная фирменная страница.
- Запрещённый системный раздел под `store_owner`: 403 без технических деталей.
- Намеренный POST-тест исключения под Разработчиком: 500, безопасная диагностика, действующая ссылка ERR-* на защищённый журнал.
- В production тот же Разработчик получает только безопасную страницу.
- В инкогнито и под другими ролями технических деталей нет в обоих режимах.
- JSON/AJAX сохраняют JSON и исходный статус; никакой диагностической HTML-карточки.
- Прямой HTTP-запрос **существующего** `storage/logs/app-YYYY-MM-DD.log` должен быть запрещён Apache (403 либо безопасное серверное запрещение). Проверьте именно файл, а не только каталог: отсутствие листинга ещё не доказывает защиту логов.

На Android Chrome проверьте вертикальный и горизонтальный экран, подтверждение/отмену и возврат со страницы ошибки. На Windows Chromium повторите эту проверку в **отдельной копии** XAMPP с собственной БД и сессиями.

## 6. Автоматические проверки

Политика без подключения к магазину (требуется PHP CLI с PDO SQLite):

```sh
php tests/error_display_mode_runtime.php
```

Ожидается: `ERR-01 policy: 36 checks passed`.

HTTP/MariaDB-набор запускает PHP-сервер на свободном localhost-порту, создаёт временную копию файлов и свои сессии. Требуются Node.js, PHP CLI с PDO MySQL/SQLite и **уже созданная тестовая БД** с именем `anabelka_err01_test` либо `anabelka_err01_test_<суффикс>`. Набор создаёт искусственных администраторов, сохраняет режимы и временно переименовывает тестовую app_settings. Не используйте БД с нужными данными; имя и localhost проверяются перед SQL. Реквизиты передайте через `ERR01_TEST_USER` / `ERR01_TEST_PASSWORD` в своей среде, не публикуя их.

```sh
ERR01_TEST_DSN='mysql:host=127.0.0.1;port=3306;dbname=anabelka_err01_test;charset=utf8mb4' \
  node --test --test-reporter=tap tests/error_display_http.test.mjs
```

Ожидается: **25 passed, 0 failed**. Без `ERR01_TEST_DSN` выполняется только тест политики, а интеграционный блок явно пропускается. При необходимости укажите CLI через `PHP_BIN`.

`tests/fixtures/error-display-router.php` — только тестовый CLI-server harness, не маршрут магазина и не установочный файл. Не регистрируйте его в рабочем Apache. Его необязательный `ERR01_BROWSER_PREVIEW=1` предназначен исключительно для одноразового стенда с искусственным owner; не используйте этот флаг при размещении магазина.

Проверка синтаксиса изменённых PHP-файлов и полный существующий Node-набор описаны в [отчёте](ERR-01-verification.md). После ручной приёмки модуля сделайте обычную ручную контрольную копию. Перенос в основной магазин — отдельное действие.
