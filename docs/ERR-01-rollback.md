# ERR-01 — безопасный откат

Модуль пока опубликован только в отдельной Git-ветке и автоматически не устанавливался. Поэтому откат основного магазина сейчас не требуется.

## Немедленно скрыть диагностику

Если раздел доступен, Разработчик выбирает «Робочий сайт» в `/Anabelka/admin/system/error-display`, подтверждает и сохраняет. Остальные роли и посетители и до этого получают безопасные сообщения.

Если интерфейс недоступен, в **БД именно той копии**, которую откатываете, можно выполнить точечный запрос через защищённое администрирование БД:

```sql
UPDATE app_settings
SET setting_value = 'production'
WHERE setting_key = 'error_display_mode';
```

Отсутствие ключа, неизвестное значение и отказ БД уже означают безопасный production. Ради этого не нужно восстанавливать или пересоздавать БД.

## Откатить код на тестовом стенде

1. Остановите только изолированный тестовый процесс/host.
2. Сохраните журналы ERR-01 и локальную конфигурацию стенда.
3. Верните предыдущую проверенную копию файлов из ручной контрольной копии, сохранив тестовый `config/database.php` и отдельные PHP-сессии. Либо подготовьте **новую отдельную копию** контрольного коммита `69fe3bcacd64b2d74e7728d6c869d61ee48f0d37` и направьте тестовый host на неё.
4. Сверьте [список файлов](ERR-01-files.md). Файлы, добавленные только ERR-01, удаляют лишь из откатываемой копии после её сохранения; новые маршруты и requires должны откатываться вместе с ними. Не оставляйте смешанный набор старого контроллера/нового шаблона или наоборот.
5. Запустите тестовую копию и проверьте безопасные 404/500, авторизацию и журнал.

Не используйте `git reset --hard`, `git clean`, force push, merge, stash или изменения `main`, `feature/category-manager`, чата и счётчика. Не переключайте рабочий магазин на тестовую конфигурацию.

## Если модуль позднее установят в основной магазин

Сначала выключите development, затем верните предыдущий согласованный комплект **файлов кода** штатным способом обновления/ручной копией. Сохраните рабочие реквизиты, фотографии, PHP-сессии, заказы и текущую БД. Полное восстановление старой БД ради отката ERR-01 может потерять новые заказы и не требуется: новых таблиц и миграций нет.

Запись `error_display_mode=production` можно оставить — прежний код её не использует. Системные логи и аудит переключений сохраняются. Глобальные настройки PHP модуль не меняет, возвращать их не требуется.
