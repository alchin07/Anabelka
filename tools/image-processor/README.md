# Anabelka Image Processor

Локальний сервіс обробки фотографій товарів.

## Призначення

Перший етап модуля:

1. вихідний файл товару читається тільки з `uploads/products`;
2. створюється окрема копія оригіналу, яку сервіс більше не змінює;
3. EXIF-орієнтація застосовується до робочої копії;
4. OpenCV перевіряє, що файл дійсно декодується як зображення;
5. профіль `model-normalize-v8` приводить кадр до єдиного формату 2:3 і спочатку використовує MediaPipe PersonDet через OpenCV DNN для визначення моделі;
6. `master.webp` створюється на полотні 1200×1800, `thumb.webp` — 320×480;
7. вільні поля заповнюються нейтральним світлим фоном `#FAFAFA`;
8. immutable-копія оригіналу зберігається в `storage/image-processor/originals`;
9. готові WebP-файли публікуються в `uploads/products/processed/<job_id>/`.

Профіль `model-normalize-v8` додає до базової геометричної стандартизації консервативне вирівнювання масштабу моделі. Основний детектор — Apache-2.0 модель MediaPipe PersonDet з OpenCV Zoo. Якщо локальна ONNX-модель ще не встановлена або не знаходить людину, процесор переходить до резервів OpenCV Haar Face, а потім HOG Person. Процесор може обрізати тільки зайвий фон навколо виявленої моделі, зберігаючи її із запасом. Якщо розпізнавання немає або безпечний crop неможливий, використовується `standard-canvas-fallback`.

v0.11 використовує три профілі фону: `original-canvas`, `studio-light` і `anabelka-brand`. Для двох нових фонів модель відділяється локальним OpenCV GrabCut. Маска додатково очищається від однорідного фону лише там, де така область безпосередньо з'єднана з краєм кадру; внутрішні світлі ділянки моделі не видаляються. Після цього відокремлені фонові острови прибираються, край маски проходить м'яке median-згладжування та distance-feather, а модель накладається на новий фон із м'якою тінню; якщо маска не проходить перевірку, процесор безпечно повертається до `original-canvas`. Генеративний ШІ не використовується.

Якщо MediaPipe впевнено знаходить модель, процесор тепер спочатку оцінює масштаб моделі за відстанню між центром плечей і центром стегон. Якщо торс займає менше 28,5% висоти кадру, застосовується консервативне `torso-normalize`: цільовий масштаб торса — близько 31% висоти, але процесор не залишає менше 72% вихідної висоти та перевіряє запас над плечима, під стегнами і по боках. Це збільшує занадто дрібно зняту модель без розтягування тіла.

Якщо торс після стандартного вписування займає понад 46% висоти кадру, застосовується `torso-zoom-out`: цільовий розмір торса — близько 40%, а фото не зменшується нижче 75% від стандартного масштабу. Це м'якше віддаляє занадто крупну модель, не спотворюючи пропорції. Якщо `torso-normalize` і `torso-zoom-out` не потрібні, а вихідний кадр лише помірно ширший за стандарт 2:3, процесор може застосувати `aspect-fill`: обрізаються тільки зайві бокові поля, кадр прив'язується до центру торса, а вся висота вихідного фото зберігається. Якщо для цього довелося б відкинути понад 20% ширини кадру, використовується попередня безпечна логіка.


Фонові профілі:
- `original-canvas` (Original+Canvas) — зберігає вихідний фон і виконує тільки геометричну нормалізацію;
- `studio-light` (Studio Light) — світлий студійний градієнт;
- `anabelka-brand` (Anabelka Brand) — м'який світло-фіолетовий брендований градієнт.

Для `studio-light` та `anabelka-brand` використовується локальна маска `opencv-grabcut`. Якщо сегментація ненадійна, результат автоматично повертається до `original-canvas`.

## Встановлення моделі MediaPipe PersonDet

Після оновлення репозиторію один раз виконайте з кореня проєкту:

```bash
bash tools/image-processor/install-person-model.sh
```

Скрипт завантажує офіційну модель OpenCV Zoo у:

```text
storage/image-processor/models/person_detection_mediapipe_2023mar.onnx
```

Перед установкою перевіряються точний розмір файла та SHA-256. Вага моделі — приблизно 12 МБ. Модель не зберігається в Git і використовується тільки локальним Image Processor.

## Запуск у Termux

З кореня проєкту:

## API

### GET /health

Повертає стан сервісу, версії Pillow/OpenCV та `person_model_ready`, щоб було видно, чи доступний основний MediaPipe PersonDet.

### POST /process

JSON:

```json
{
  "source": "uploads/products/example.jpg"
}
```

Дозволені тільки файли безпосередньо з `uploads/products`.
Абсолютні шляхи, `..` та інші каталоги відхиляються.

Результат містить:

- `processor_version: 0.5`;
- `profile: model-normalize-v2`;
- блок `normalization` з інформацією про детекцію моделі та застосований метод;
- immutable original copy;
- `master.webp` 1200×1800;
- `thumb.webp` 320×480.

Сервіс не перезаписує вихідну фотографію товару. Геометрія вихідного фото не спотворюється: зображення масштабується зі збереженням пропорцій і центрується на єдиному полотні.


## Прив'язка до товарного фото

Після етапу 0.2 PHP більше не повинен приймати шлях до файла від
браузера для штатної обробки. Адмін-операція передає тільки
`image_id` з `product_gallery_images`.

Серверна послідовність:

```text
image_id
  -> ProductImage::findById()
  -> перевірений source_path із БД
  -> ImageProcessorClient
  -> Python /process
  -> product_image_processing
```

Таблиця `product_image_processing` зберігає останній стан обробки,
SHA-256 оригіналу, розміри й вагу source/master/thumb, шляхи до
похідних файлів, версію процесора та час обробки.

Повторна обробка не видаляє і не перезаписує попередню immutable-копію
оригіналу в storage. Новий job отримує окрему папку.

Для v0.11 PHP зберігає профіль разом із версією у полі
`processor_version`, наприклад `0.11:model-normalize-v8`. Фоновий профіль і діагностика маски зберігаються у normalization JSON.

Методи нормалізації:
- `mediapipe-persondet` — MediaPipe PersonDet знайшов модель і виконано безпечне кадрування;
  - `crop_strategy: torso-normalize` — занадто дрібну модель наближено за плечі↔стегна;
  - `crop_strategy: torso-zoom-out` — занадто крупну модель м'яко віддалено до цільового масштабу торса;
  - `crop_strategy: aspect-fill` — прибрано тільки помірний горизонтальний надлишок, щоб отримати 2:3 без полів;
  - `crop_strategy: subject-bbox` — використано межі знайденої моделі;
- `mediapipe-persondet-no-crop` — MediaPipe PersonDet знайшов модель, але crop був би небезпечним;
- `opencv-haar-face-subject` — обличчя знайдено, оцінено область моделі й виконано безпечне кадрування;
- `opencv-haar-face-subject-no-crop` — обличчя знайдено, але crop був би небезпечним;
- `opencv-hog-person` — резервний HOG знайшов людину й виконано безпечне кадрування;
- `opencv-hog-person-no-crop` — HOG знайшов людину, але crop не застосовано;
- `standard-canvas-fallback` — модель не знайдена, використано стандартний холст 2:3.

## MODNet і повторна перевірка GrabCut

Для `studio-light` та `anabelka-brand` початкова маршрутизація залишається
незмінною: складний фон може одразу використовувати MODNet, однорідний —
GrabCut. Після штатного очищення GrabCut виконується додаткова перевірка
маски на зменшеному зображенні з максимальною стороною 512 px.

Повторна перевірка шукає великі широкі області, схожі на прозорі однорідні
зразки фону на краях фото і з'єднані з краєм вихідного кадру. Допускається
обмежена зміна яскравості через тіні, але близькість кольору сама по собі
не дозволяє видаляти пікселі. Залишок повинен займати щонайменше 2% кадру
і 8% переднього плану GrabCut, мати товсте ядро та значну площу компонента.
Додатково перевіряється неперервність вихідного фону від прозорих країв:
шлях не повинен перетинати контур моделі. Допуск локальної зміни кольору
оцінюється на прозорих зразках і обмежений; ширший допуск палітри для тіней
не застосовується до контурів. Дрібна текстура, зокрема слабкі чи рідкі
стібки біля межі тканини, захищає і сусідні пікселі матеріалу. Вузькі деталі
не успадковують підтвердження від широкого залишку, до якого приєднані.
Для розмитого зменшенням переходу тіні дозволені ще два пікселі перевірки
лише біля двох різних ділянок фону, незалежно з'єднаних із прозорим краєм.
Тільки підтверджений після цих перевірок залишок допускає виклик MODNet.

MODNet приймається, якщо площа його маски допустима, виявлений залишок
фону зменшується щонайменше вдвічі та на 1% площі кадру, а захищений
передній план зберігається як загалом, так і в окремих просторових зонах.
Додатково перевіряється, що маска не повертає раніше виключені області
фону іншого кольору. Захищена маска формується після остаточного визначення
залишку фону: підтверджений фон не отримує захист повторно через знаходження
всередині детекторної рамки. Неоднозначні області волосся, рук, тіла й тканини
залишаються захищеними за ознаками вихідного зображення. Перетин захищеної
маски з підтвердженим залишком дорівнює нулю. Загальні й локальні пороги
збереження переднього плану не знижені. Менший
`mask_foreground_ratio` сам по собі не є підставою для заміни.

При помилці перевірки, помилці/тайм-ауті MODNet або недостатньому покращенні
використовується вже очищений GrabCut. Після невдалого початкового виклику
MODNet повторної спроби немає. На одне фото викликається максимум один
worker. MODNet працює в окремому процесі з попереднім тайм-аутом 45 s
і обмеженнями ORT для Android; м'яка alpha MODNet не проходить очищення GrabCut.

`original-canvas`, детектор, геометрія та всі чотири стратегії кадрування
не змінені. Перевірка навмисно консервативна: при неоднозначності вона може
залишити GrabCut навіть тоді, коли MODNet візуально кращий. Синтетичні тести
не замінюють перевірку реальних фото на Android.

### Контроль на Android / Termux

Спочатку переконайтеся, що поточна гілка — `feature/category-manager`,
і перегляньте незакомічені зміни. Оновлюйте її без merge в `main`:

```bash
cd /storage/emulated/0/htdocs/Anabelka
git status --short
git branch --show-current
git pull --ff-only origin feature/category-manager
python -B tools/image-processor/check_modnet_fallback.py
```

За замовчуванням перевіряються обидва контрольні джерела:

- `20260904-111401-94806794d9042bb1.jpg` — проблемний коричневий фон;
- `20260904-082048-f82e27bc5a56b2b1.jpg` — контрольний крупний план.

Для другого фонового профілю:

```bash
python -B tools/image-processor/check_modnet_fallback.py --background-profile anabelka-brand
```

Скрипт послідовно порівнює Original+Canvas, примусовий GrabCut, примусовий
MODNet і автоматичний вибір. Зберігає окремі `master`-прев'ю, `comparison.jpg`
та `diagnostics.json` у новій папці
`storage/image-processor/modnet-fallback-check/<timestamp>/<source-stem>/`.
У діагностиці є фактичний `mask_method`, площа маски, crop/zoom, час виконання
(разом із записом WebP), кількість викликів worker, його помилки та SHA-256
джерела до/після. Примусовий MODNet при помилці може фактично стати GrabCut —
дивіться застосований метод, а не заголовок колонки.

Скрипт не записує дані товарів чи БД і не перезаписує вихідні фото або попередні
порівняння. Для штатного сервісу після оновлення потрібен звичайний перезапуск
Image Processor, щоб він завантажив новий код.

Залишаються ручні перевірки: великі коричневі залишки на проблемному фото;
якість контрольної блондинки; контури волосся, рук, тіла, мережива та білизни;
незмінність crop/zoom і пропорцій; фактичний метод; час і стабільність Android.
Оригінальні контрольні фото та ONNX-модель недоступні в середовищі автоматичних
перевірок цієї правки, тому візуальна прийнятність і продуктивність не підтверджені.
