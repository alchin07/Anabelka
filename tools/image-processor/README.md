# Anabelka Image Processor

Локальний сервіс обробки фотографій товарів без ШІ.

## Призначення

Перший етап модуля:

1. вихідний файл товару читається тільки з `uploads/products`;
2. створюється окрема копія оригіналу, яку сервіс більше не змінює;
3. EXIF-орієнтація застосовується до робочої копії;
4. OpenCV перевіряє, що файл дійсно декодується як зображення;
5. профіль `model-normalize-v2` приводить кадр до єдиного формату 2:3 і спочатку використовує MediaPipe PersonDet через OpenCV DNN для визначення моделі;
6. `master.webp` створюється на полотні 1200×1800, `thumb.webp` — 320×480;
7. вільні поля заповнюються нейтральним світлим фоном `#FAFAFA`;
8. immutable-копія оригіналу зберігається в `storage/image-processor/originals`;
9. готові WebP-файли публікуються в `uploads/products/processed/<job_id>/`.

Профіль `model-normalize-v2` додає до базової геометричної стандартизації консервативне вирівнювання масштабу моделі. Основний детектор — Apache-2.0 модель MediaPipe PersonDet з OpenCV Zoo. Якщо локальна ONNX-модель ще не встановлена або не знаходить людину, процесор переходить до резервів OpenCV Haar Face, а потім HOG Person. Процесор може обрізати тільки зайвий фон навколо виявленої моделі, зберігаючи її із запасом. Якщо розпізнавання немає або безпечний crop неможливий, використовується `standard-canvas-fallback`.

v0.5 не змінює фон усередині вихідного фото, не домальовує частини тіла та не використовує генеративний ШІ.

Якщо MediaPipe впевнено знаходить модель, процесор тепер спочатку оцінює масштаб моделі за відстанню між центром плечей і центром стегон. Якщо торс займає менше 28,5% висоти кадру, застосовується консервативне `torso-normalize`: цільовий масштаб торса — близько 31% висоти, але процесор не залишає менше 72% вихідної висоти та перевіряє запас над плечима, під стегнами і по боках. Це збільшує занадто дрібно зняту модель без розтягування тіла.

Якщо `torso-normalize` не потрібен або не проходить перевірки безпеки, а вихідний кадр лише помірно ширший за стандарт 2:3, процесор може застосувати `aspect-fill`: обрізаються тільки зайві бокові поля, кадр прив'язується до центру торса, а вся висота вихідного фото зберігається. Якщо для цього довелося б відкинути понад 20% ширини кадру, використовується попередня безпечна логіка.

## Встановлення моделі MediaPipe PersonDet

Після оновлення репозиторію один раз виконайте з кореня проєкту:

```bash
bash tools/image-processor/install-person-model.sh
```

Скрипт завантажує офіційну модель OpenCV Zoo у:

```text
storage/image-processor/models/person_detection_mediapipe_2023mar.onnx
```

Перед установкою перевіряються точний розмір файла та SHA-256. Вага моделі — приблизно 12 МБ. Модель не зберігається в Git і використовується тільки локальним Image Processor.

## Запуск у Termux

З кореня проєкту:

```bash
python tools/image-processor/server.py
```

За замовчуванням сервіс слухає тільки:

```text
http://127.0.0.1:8765
```

Перевірка:

```text
http://127.0.0.1:8765/health
```

PHP-перевірка після входу в адмін-панель:

```text
/Anabelka/admin/image-processor/health
```

## API

### GET /health

Повертає стан сервісу, версії Pillow/OpenCV та `person_model_ready`, щоб було видно, чи доступний основний MediaPipe PersonDet.

### POST /process

JSON:

```json
{
  "source": "uploads/products/example.jpg"
}
```

Дозволені тільки файли безпосередньо з `uploads/products`.
Абсолютні шляхи, `..` та інші каталоги відхиляються.

Результат містить:

- `processor_version: 0.5`;
- `profile: model-normalize-v2`;
- блок `normalization` з інформацією про детекцію моделі та застосований метод;
- immutable original copy;
- `master.webp` 1200×1800;
- `thumb.webp` 320×480.

Сервіс не перезаписує вихідну фотографію товару. Геометрія вихідного фото не спотворюється: зображення масштабується зі збереженням пропорцій і центрується на єдиному полотні.


## Прив'язка до товарного фото

Після етапу 0.2 PHP більше не повинен приймати шлях до файла від
браузера для штатної обробки. Адмін-операція передає тільки
`image_id` з `product_gallery_images`.

Серверна послідовність:

```text
image_id
  -> ProductImage::findById()
  -> перевірений source_path із БД
  -> ImageProcessorClient
  -> Python /process
  -> product_image_processing
```

Таблиця `product_image_processing` зберігає останній стан обробки,
SHA-256 оригіналу, розміри й вагу source/master/thumb, шляхи до
похідних файлів, версію процесора та час обробки.

Повторна обробка не видаляє і не перезаписує попередню immutable-копію
оригіналу в storage. Новий job отримує окрему папку.

Для v0.5 PHP зберігає профіль разом із версією у полі
`processor_version`, наприклад `0.5:model-normalize-v2`.

Методи нормалізації:
- `mediapipe-persondet` — MediaPipe PersonDet знайшов модель і виконано безпечне кадрування;
  - `crop_strategy: torso-normalize` — масштаб моделі вирівняно за плечі↔стегна;
  - `crop_strategy: aspect-fill` — прибрано тільки помірний горизонтальний надлишок, щоб отримати 2:3 без полів;
  - `crop_strategy: subject-bbox` — використано межі знайденої моделі;
- `mediapipe-persondet-no-crop` — MediaPipe PersonDet знайшов модель, але crop був би небезпечним;
- `opencv-haar-face-subject` — обличчя знайдено, оцінено область моделі й виконано безпечне кадрування;
- `opencv-haar-face-subject-no-crop` — обличчя знайдено, але crop був би небезпечним;
- `opencv-hog-person` — резервний HOG знайшов людину й виконано безпечне кадрування;
- `opencv-hog-person-no-crop` — HOG знайшов людину, але crop не застосовано;
- `standard-canvas-fallback` — модель не знайдена, використано стандартний холст 2:3.
